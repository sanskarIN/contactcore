# Data Model

ContactCore treats a contact as one aggregate with scalar identity/profile fields plus repeated child collections. The domain model lives in `src/ContactCore.Domain/ContactModels.cs`; the relational mapping lives in `DatabaseMigrator.cs` and `SqliteContactRepository.cs`.

## Contact aggregate

`Contact` contains:

| Property | Type | Persistence | Notes |
|---|---|---|---|
| `Id` | `Guid` | `contacts.id` | Primary identity; generated by default. |
| `GivenName` | `string` | `contacts.given_name` | Empty allowed; max 120 characters. |
| `FamilyName` | `string` | `contacts.family_name` | Empty allowed; max 120 characters. |
| `Nickname` | `string` | `contacts.nickname` | Empty allowed; max 120 characters. |
| `Birthday` | `DateOnly?` | `contacts.birthday` | Stored as ISO `yyyy-MM-dd` text. |
| `Notes` | `string` | `contacts.notes` | Empty allowed; max 20,000 characters. |
| `IsFavorite` | `bool` | `contacts.is_favorite` | Stored as integer 0/1. |
| `IsArchived` | `bool` | `contacts.is_archived` | Stored as integer 0/1. |
| `CreatedAt` | `DateTimeOffset` | `contacts.created_at` | Stored using round-trip `O` format. |
| `UpdatedAt` | `DateTimeOffset` | `contacts.updated_at` | Refreshed by application save/import/merge flows. |
| `Phones` | list | `phones` | Contact-owned repeated rows. |
| `Emails` | list | `emails` | Contact-owned repeated rows. |
| `Addresses` | list | `addresses` | Contact-owned repeated rows. |
| `Organizations` | list | `organizations` | Contact-owned repeated rows. |
| `Groups` | list | `groups` + `contact_groups` | Shared names with many-to-many links. |
| `Tags` | list | `tags` + `contact_tags` | Shared names with many-to-many links. |

`DisplayName` prefers `GivenName + FamilyName`, then nickname, then `Unnamed contact`.

`DeepCopy()` creates a new aggregate object with the same contact identity and scalar values and copies each child record collection. Record children are immutable, so the copied lists can be changed independently while values remain safely shared.

## Repeated field records

### Phones

`ContactPhone(Guid Id, string Label, string Number, ContactFieldKind Kind)` maps to `phones(id, contact_id, label, number, kind)`.

`ContactFieldKind` contains `Home`, `Work`, `Mobile`, and `Other`. Phone validation currently accepts digits plus `+ ( ) space . -`, with a total length of 3 to 40 characters.

### Emails

`ContactEmail(Guid Id, string Label, string Address, ContactFieldKind Kind)` maps to `emails(id, contact_id, label, address, kind)`. Address validation uses `System.Net.Mail.MailAddress`, caps length at 320, and requires the normalized parser result to equal the supplied address ignoring case.

### Addresses

`ContactAddress(Guid Id, string Label, string Street, string City, string Region, string PostalCode, string Country)` maps to the `addresses` table. The current domain validation layer does not impose per-address-field length rules; UI and persistence consumers should therefore avoid assuming such limits until explicitly introduced.

### Organizations

`ContactOrganization(Guid Id, string Name, string? Title, string? Department)` maps to `organizations`. Duplicate merge equivalence compares normalized organization name, title, and department.

### Groups and tags

`ContactGroup` and `ContactTag` each contain an ID and name. SQLite enforces case-insensitive unique names with `COLLATE NOCASE`. Linking tables use `(contact_id, group_id)` and `(contact_id, tag_id)` composite primary keys.

## SQLite tables

Schema version 1 creates:

- `contacts`
- `phones`
- `emails`
- `addresses`
- `organizations`
- `groups`
- `tags`
- `contact_groups`
- `contact_tags`
- `schema_migrations` (created by the migrator before versioned migrations run)

Schema version 2 adds:

- `app_metadata`
- `app_metadata['schema_family'] = 'contactcore'`

The schema-family marker is used by backup/restore validation to distinguish a valid ContactCore database from unrelated valid SQLite files.

## Foreign keys and delete behavior

Child tables reference `contacts(id)` with `ON DELETE CASCADE`. Link tables cascade when contacts/groups/tags are deleted. `SqliteConnectionFactory` enables `PRAGMA foreign_keys = ON` for every opened connection.

## Write model and atomicity

`SqliteContactRepository.UpsertManyAsync` opens one connection and one transaction for the complete supplied batch. Each contact is upserted into `contacts`, then its contact-owned child/link rows are replaced inside the same transaction. A failure causes transaction rollback instead of committing a partially imported batch.

For a single contact, `UpsertAsync` delegates to the same bulk path with a one-item collection.

## Child replacement strategy

When an existing contact is saved, repository code deletes that contact's rows from `phones`, `emails`, `addresses`, `organizations`, `contact_groups`, and `contact_tags`, then inserts the current aggregate state. This is simple and deterministic: the persisted child collections match the aggregate passed to the repository after commit.

Group/tag dictionary rows are not mass-deleted during contact saves. They are inserted by case-insensitive name if absent and linked using the name lookup.

## Search indexes

The initial schema defines:

- `ix_contacts_name` on `(family_name, given_name)`;
- `ix_contacts_flags` on `(is_archived, is_favorite)`;
- `ix_phones_number` on `phones(number)`;
- `ix_emails_address` on `emails(address COLLATE NOCASE)`.

Current free-text search uses `LIKE` across names and `EXISTS` subqueries for phone/email. Group/tag filters use relationship `EXISTS` queries. Large datasets should be benchmarked before claiming a specific scalability threshold.

## Search escaping

User text used in `LIKE` clauses is escaped for backslash, `%`, and `_`, and queries specify `ESCAPE '\'`. This prevents those characters from unintentionally acting as SQL pattern wildcards. Values are still passed as parameters.

## Normalization

`TextNormalizer.SearchKey`:

1. treats null/whitespace as empty;
2. decomposes Unicode to Form D;
3. removes non-spacing marks;
4. lowercases invariantly;
5. recomposes to Form C;
6. trims surrounding whitespace.

`TextNormalizer.PhoneKey` keeps only digits. Duplicate detection and merge use these helpers to compare user-facing values more consistently.

## Migration compatibility

`DatabaseMigrator` tracks applied versions in `schema_migrations`. If a database reports a version newer than `LatestSchemaVersion`, ContactCore throws `NotSupportedException` instead of attempting an unsafe downgrade. Each pending migration runs in a transaction, and schema identity is checked after migration.

Any new schema migration should be append-only in version ordering, deterministic, transactional where SQLite permits it, accompanied by upgrade tests, and documented here plus in the changelog.
