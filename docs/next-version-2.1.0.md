# ContactCore 2.1.0 — Next Version Work Plan

ContactCore 2.1.0 is the next feature line after the verified 2.0.12 cross-platform release baseline. This document tracks implemented work separately from future work so release claims stay evidence-based.

## Current 2.1.0 implementation

- Source version advanced from 2.0.12 to 2.1.0.
- Repeated contact fields now have deterministic move-up and move-down commands for phones, emails, addresses, organizations, groups, and tags.
- The portable Avalonia editor exposes those controls in the shared UI, so the capability applies to desktop, Android, iOS/iPadOS, and Browser targets that use `ContactCore.UI`.
- Reordering mutates only collection position. Existing row IDs and row values are not regenerated by the move operation.
- `ToContact()` emits repeatable rows in their current draft order, so saved aggregate order follows the user's editor order.
- Portable UI tests cover boundary no-ops, movement in both directions, every repeatable collection category, and emitted save order for phones/emails.
- `Microsoft.NET.Test.Sdk` is advanced from 18.8.1 to 18.9.0 on the 2.1.0 line.

## Verification gate for this branch

Before 2.1.0 can be considered release-ready, the exact branch/PR head must pass the same baseline quality gates established for 2.0.12:

- core restore, format verification, Release build, and tests on Ubuntu;
- core restore, format verification, Release build, and tests on Windows;
- core restore, format verification, Release build, and tests on macOS;
- Browser/WebAssembly Release build;
- Android `android-arm64` Release build;
- iOS `iossimulator-arm64` Release build with the documented compatible Xcode selection;
- CodeQL.

Reordering is intentionally implemented with explicit accessible buttons first. Pointer drag/drop can be evaluated later as an enhancement only if it preserves keyboard, touch, screen-reader, and trim/AOT behavior across the supported targets.

## Remaining 2.1.0 candidates

### Product and UX

- global group/tag taxonomy management with safe rename/merge/delete semantics;
- undo/recovery UX for destructive or high-impact edits;
- keyboard shortcuts for repeated-field movement where focus semantics are unambiguous;
- accessibility review of reorder announcements and focus retention.

### Browser and resilience

- real IndexedDB automation harness;
- cross-tab conflict detection/strategy;
- deeper native restore cleanup and failure-injection coverage.

### Performance

- reproducible 100/1,000/10,000-contact benchmark fixtures;
- query/SQL amplification measurements;
- Browser snapshot-write benchmarks;
- pagination/list projection evaluation;
- duplicate-candidate generation optimization if measurements justify it.

### Distribution and security

- production SQLCipher provider/package/licensing decision if encrypted-at-rest native storage is selected;
- native secure-secret-store abstraction for sensitive runtime values;
- Windows signing/installer work;
- macOS signing/notarization;
- Android production signing/store publication;
- iOS signed-device/TestFlight/App Store pipeline;
- additional package-manager formats.

## Release discipline

Do not tag or publish 2.1.0 from this branch until 2.0.12 is merged into `main`, the 2.1.0 integration branch is rebased/retargeted cleanly onto that released baseline, and exact-head CI/CodeQL passes. Production signing and physical-device/store certification require real maintainer-controlled credentials and external verification; they must not be represented as completed by source-only CI.
