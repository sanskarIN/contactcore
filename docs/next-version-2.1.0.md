# ContactCore 2.1.0 — Next Version Work Plan

ContactCore 2.1.0 is the next feature line based on the exact 2.0.12 release-candidate source head. The 2.0.12 integration is still gated on its final iOS simulator build at the time of this document update, so this file does not prematurely describe that baseline as released or fully verified. Implemented work is kept separate from future work so release claims stay evidence-based.

## Current 2.1.0 implementation

- Source version advanced from 2.0.12 to 2.1.0.
- Repeated contact fields now have deterministic move-up and move-down commands for phones, emails, addresses, organizations, groups, and tags.
- The portable `ContactCore.UI` Avalonia editor exposes those controls for Android, iOS/iPadOS, Browser, and other heads that compose the portable UI.
- The mature `ContactCore.Desktop` shell has its own draft/view-model implementation; it now has matching reorder commands and visible reorder controls instead of relying on bindings to commands that exist only in the portable UI.
- Reordering mutates only collection position. Existing row IDs and row values are not regenerated by the move operation.
- Both draft implementations emit repeatable rows in their current draft order, so saved aggregate order follows the user's editor order.
- Portable UI tests cover boundary no-ops, movement in both directions, every repeatable collection category, and emitted save order.
- Desktop tests cover every repeated-field command plus boundary, identity-preservation, and saved-order behavior.
- About/version text in both UI stacks now derives from built assembly metadata rather than a duplicated stale literal.
- A portable UI metadata regression test protects the assembly-version About behavior.
- `Microsoft.NET.Test.Sdk` is advanced from 18.8.1 to 18.9.0 on the 2.1.0 line.

## Verification gate for this branch

Before 2.1.0 can be considered release-ready, the exact branch/PR head must pass the same baseline quality gates established for the 2.0.12 candidate:

- core restore, format verification, Release build, and tests on Ubuntu;
- core restore, format verification, Release build, and tests on Windows;
- core restore, format verification, Release build, and tests on macOS;
- Browser/WebAssembly Release build;
- Android `android-arm64` Release build;
- iOS `iossimulator-arm64` Release build with the documented compatible Xcode selection;
- CodeQL.

The repository's pull-request CI/CodeQL workflows target PRs whose base is `main`. PR #17 therefore remains a draft review branch while PR #4 is open. Once the verified 2.0.12 integration lands on `main`, PR #17 must be retargeted to `main` so normal exact-head validation runs against the real integration candidate.

Reordering is intentionally implemented with explicit accessible buttons first. Pointer drag/drop can be evaluated later as an enhancement only if it preserves keyboard, touch, screen-reader, focus, and trim/AOT behavior across the supported targets.

## Remaining 2.1.0 candidates

### Product and UX

- global group/tag taxonomy management with safe rename/merge/delete semantics;
- undo/recovery UX for destructive or high-impact edits;
- keyboard shortcuts for repeated-field movement where focus semantics are unambiguous;
- accessibility review of reorder announcements and focus retention;
- reduce duplicated Desktop/portable draft logic where doing so does not weaken the mature desktop experience or trim/AOT behavior.

### Browser and resilience

- real IndexedDB automation harness;
- cross-tab conflict detection/strategy;
- deeper native restore cleanup and failure-injection coverage.

### Performance

- reproducible 100/1,000/10,000-contact benchmark fixtures;
- query/SQL amplification measurements;
- Browser snapshot-write benchmarks;
- pagination/list projection evaluation;
- duplicate-candidate generation optimization if measurements justify it.

### Distribution and security

- production SQLCipher provider/package/licensing decision if encrypted-at-rest native storage is selected;
- native secure-secret-store abstraction for sensitive runtime values;
- Windows signing/installer work;
- macOS signing/notarization;
- Android production signing/store publication;
- iOS signed-device/TestFlight/App Store pipeline;
- additional package-manager formats.

## Release discipline

Do not tag or publish 2.1.0 from this branch until 2.0.12 is merged into `main`, PR #17 is cleanly retargeted/reconciled onto that released baseline, and exact-head CI/CodeQL passes. Production signing and physical-device/store certification require real maintainer-controlled credentials and external verification; they must not be represented as completed by source-only CI.
